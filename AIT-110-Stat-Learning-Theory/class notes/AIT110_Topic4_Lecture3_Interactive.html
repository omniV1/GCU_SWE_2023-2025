Bootstrapping

The Core Idea

A bootstrap sample is created by randomly selecting n data points with replacement from a dataset of n points.

Because we sample with replacement, some data points appear multiple times and some are left out entirely. About 63.2% of original points appear in each sample on average.

Why Bootstrapping?

We only have one dataset, but we want to estimate how a model behaves on different possible datasets. Bootstrap sampling lets us simulate multiple draws from the population.

Classic Use Case: Build a 95% confidence interval around a statistic (like the median):

  1. Take 1000 bootstrap samples
  2. Calculate the median of each sample
  3. The 95% CI is the 25th and 975th largest values

    size=len(X_train),    # same size as original
    replace=True          # KEY: with replacement!

Bagging — Bootstrap Aggregation

The Big Idea

If we had unlimited data, we'd train many models on different datasets and average them. Since we don't, we simulate multiple datasets using bootstrapping, then aggregate the predictions.

How Bagging Works

  1. Create B bootstrap samples Draw B samples of size n (with replacement) from your training data.
  2. Train a model on each sample Typically a high-variance, low-bias model — like a fully grown decision tree (no pruning).
  3. Aggregate predictions For classification: majority vote. For regression: average the predictions.
Interactive Demo — Variance Reduction with Bagging

Drag the slider to see how ensemble size affects variance. Each tree has individual noise, but the average is much more stable.

Why Variance Reduction < √n ?

Theoretically, averaging n independent models reduces variance by √n. But bootstrap samples all come from the same original dataset, so the trees are correlated. Correlated models don't reduce variance as much.

Var(avg of n correlated models) = ρσ² + (1-ρ)σ²/n

where ρ is the correlation between trees. Higher correlation → less variance reduction. This is exactly what Random Forest addresses!

Pros of Bagging

  • Dramatically reduces variance
  • Works well out of the box
  • No feature scaling needed
  • Models non-linear relationships

Cons of Bagging

  • Trees are still correlated
  • Expensive to train (many trees)
  • Not interpretable (black box)
  • Variance reduction limited by ρ

Random Forest

Random Forest = Bagging + One Extra Trick

Random Forest improves on Bagging by de-correlating the trees using Subspace Sampling: at each split, only a random subset of m features is considered.

Typical m = √p (for classification)  or  m = p/3 (for regression)

where p = total number of features. This prevents the same strong feature from always being chosen first, making trees more diverse and less correlated.

Bagging vs Random Forest — The Key Difference

Bagging

Each split: considers ALL features
→ Strong features dominate
→ Trees look similar
→ High correlation ρ
→ Less variance reduction

Random Forest

Each split: considers only √p features
→ Weaker features get chances
→ Trees look different
→ Lower correlation ρ
→ Better variance reduction

Random Forest Key Parameters

ParameterWhat It ControlsEffect
n_estimatorsTotal number of treesMore trees → lower variance (but more compute)
max_featuresFeatures per split (m)Lower m → less correlated trees, but weaker individual trees
max_depthMax tree depthShallower → lower variance, higher bias
min_samples_leafMin samples at leavesLarger → smoother predictions, less overfit
criterionSplit measure (gini/entropy)Usually similar performance

Pros of Random Forest

  • Near state-of-the-art performance
  • Great out-of-the-box (few tuning needs)
  • No feature scaling required
  • Handles non-linear relationships
  • Parallelizable (trees independent)

Cons of Random Forest

  • Expensive to train (though parallelizable)
  • Not interpretable — black box
  • Memory-intensive for large forests
  • Slower predictions than a single tree

Out-of-Bag (OOB) Error

A Free Validation Set!

Because each bootstrap sample leaves out ~37% of the training data, each data point is out-of-bag for many trees. We can use those "unseen" predictions to estimate test error — without needing a separate validation set.

How OOB Error Works

  1. For each data point x_i Identify all trees that did NOT see x_i in their bootstrap sample.
  2. Predict using those trees only Average (regression) or majority vote (classification) among those trees.
  3. Compare to actual y_i This gives an unbiased estimate of test error.
  4. Average across all data points OOB score ≈ test set score. The lecture example found OOB score = 0.9528.
Interactive Demo — Visualize OOB

10 data points, 5 trees. Green = included in bootstrap sample, Gray = out-of-bag. Each row is a tree, each column is a data point.

Key Insight

OOB error lets you tune hyperparameters without touching your test set. Set oob_score=True in scikit-learn's RandomForestClassifier to get it automatically.

Feature Importance

Why Feature Importance Matters

Random Forests sacrifice interpretability for accuracy. Feature importance partially restores that interpretability by answering: which features actually drive predictions?

Business Example

In churn analysis, knowing why customers churn (feature importance) is often more valuable than just who will churn (prediction).

Method 1: Mean Decrease in Impurity (MDI / Gini Importance) ▼

How much does each feature reduce impurity across all splits in all trees?

  1. For each tree, each split Calculate the impurity decrease: (impurity before) − weighted (impurity after).
  2. Sum by feature For each feature, sum all impurity decreases across splits that used that feature. Divide by total information gain = feature importance for one tree.
  3. Average across forest Average the Gini importance for each feature across all trees.
Importance(feature j) = avg over trees [ Σ splits using j (ΔImpurity) / Σ all splits (ΔImpurity) ]

Caution

MDI is biased toward high-cardinality features (features with many unique values). A feature with 100 unique values will almost always look more important than one with 2.

Method 2: Permutation Feature Importance (OOB-based) ▼

What happens to OOB score if we randomly scramble one feature's values?

  1. Calculate baseline OOB score Get OOB score with original data. This is your reference point.
  2. For each feature j Randomly shuffle the values of feature j in the OOB samples. Predict again. Record the drop in score.
  3. Repeat and average Average the score decrease across many runs and all trees.
Intuition

If shuffling a feature causes a big drop in accuracy, the model was relying on that feature. If shuffling changes nothing, the feature wasn't important.

Why This Method is Better

No bias toward high-cardinality features. More reliable and model-agnostic. Lecture baseline OOB score: 0.9528.

Ensemble Intuition & Math

Why Do Ensembles Work? (From the Lecture)

Suppose we have 5 independent binary classifiers, each 70% accurate. The majority vote is correct if 3 or more agree:

P(majority correct) = C(5,5)·0.7⁵ + C(5,4)·0.7⁴·0.3 + C(5,3)·0.7³·0.3² ≈ 83.2%

With 55 classifiers, this reaches 99.9% accuracy!

Interactive Demo — Ensemble Accuracy Calculator

The Catch: Independence

The huge accuracy gains assume independent classifiers. In practice, all trees are trained on the same dataset, so they're correlated. This is why:

  • We use bootstrap sampling (different data → different trees)
  • Random Forest adds subspace sampling (different features → even more different trees)
  • The goal is to maximize diversity while maintaining individual accuracy

Bias-Variance in Ensembles

↓
Variance
Averaging reduces variability
≈
Bias
Individual trees are low bias (unpruned)
✓
Result
Better generalization overall

An unpruned decision tree has near-zero bias (memorizes training data) but high variance (changes drastically with new data). Bagging/RF keeps the low bias and reduces the variance.
